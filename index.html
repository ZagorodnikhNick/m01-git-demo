Проверяемые состояния

Три точки рабочего процесса

  1. 01

    Local

    Файлы открываются в браузере, а Git фиксирует понятную историю изменений.

  2. 02

    GitHub

    Ветка и Pull Request делают границу изменения видимой до merge.

  3. 03

    Pages

    Ветка main и каталог /(root) становятся источником публичного сайта.

Ожидаемый результат

Один проект — несколько подтверждений

  • чистое состояние рабочего каталога;
  • осмысленные commits в истории;
  • проверенное изменение после Pull Request;
  • рабочий публичный URL.
